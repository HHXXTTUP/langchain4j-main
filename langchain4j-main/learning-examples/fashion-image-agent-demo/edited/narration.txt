大家好，我是一名传统程序员，也正在用一个真实的服装替换项目学习 AI 应用和 LangChain4j。今天不依赖抽象的示例，直接看这套网站怎样把提示词、图片生成、服装理解和质量检查串成一条完整链路。

首先来到工作台。这里输入人物描述，例如卧室美女、沙滩美女或办公室美女，也可以用分号一次提交多个描述，系统会拆成多条任务排队执行。提交之后，LangChain4j 会先把简单描述扩写成人物、环境、光线和构图提示词，再交给 RunningHub 生成图片。人物生成完成后，还会经过视觉质检，检查图片是否完整，以及人物和提示词是否一致。

右侧是 Agent 流程。每一个步骤都有明确状态：提示词导演、人物创作、人物质检、服装挑选、服装理解、换装工具和视觉质检。这里的重点是把一次 API 调用拆成可观察、可重试的业务步骤。服装替换时保留原图人物的脸部、姿势和背景，只读取服装参考图的服装、发型和配饰细节。综合评分达到标准后直接完成，并把遗漏经验沉淀下来。

接着看任务列表。图片生成页展示每条任务的原图、换装结果、人物质检分数和当前步骤。分数达到七十分以上会用颜色区分。已完成的图片任务还可以继续创建视频生成任务，视频任务会进入独立的队列，避免图片任务和长时间的视频任务互相干扰。

资料库页面分成图片和视频两个子菜单。图片资料来自本地 clothing 目录，点击生成本地资料后，视觉模型会分析服装的颜色、材质、版型、发饰和配饰，并将结构化结果写入 MySQL。历史换装任务完成后，也会提取可复用经验。后续通过 RAG 检索这些资料，为服装匹配和提示词补充提供依据。

最后是日志页面。这里集中展示应用运行日志和异常堆栈，包括接口请求、轮询、下载、审核、显存不足和任务停止等信息。遇到问题时可以直接复制日志定位原因。这样我们学习到的不只是调用接口，还包括 Agent 编排、RAG 检索、异步任务、质量控制和可观测性。

这就是一个老款程序员逐步进入 AI 应用开发的过程：先跑通业务，再把每一步变成可解释、可验证、可复用的模块。
